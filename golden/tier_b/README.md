# Tier B — real bottle photographs

Tier A is generated by our own renderer and then tested against our own pipeline. It
proves the pipeline can read *our renderer*. Real bottles have commercial typefaces, foil,
letterpress texture, curvature, and marketing clutter the generator will never produce, so
a Tier A number on its own is an upper bound, not an answer.

Tier B is the answer. **It never gates CI** — small n, nondeterministic, live model — and
it is reported on every run. The gap between the two numbers is a published metric.

The harness, the manifest format, the loader and the reporting are all in place. Adding
photographs is the only remaining step.

## Adding photographs

1. **Shoot 6–8.** The shot list is in `manifest.json` under `capture_guide`: mixed
   commodity, front *and* back of at least two products, 2–3 straight-on, one ~30° off
   axis, one dim, one with flash on curved glass. Keep the HEIC originals.
2. **Drop the files in `images/`.** Any name; the manifest points at them.
3. **Add a row per label to `labels` in `manifest.json`** (shape below).
4. **Bootstrap the ground truth.** Run the label through the app, confirm or correct each
   field by eye, and record the corrected values in `application`. Transcribing seven
   fields by hand from scratch is slower and more error-prone than correcting a draft.
   Flip `ground_truth` to `hand_verified` once a human has signed the row off.
5. **Check it loads.** `python -m eval.run --tier b` validates every row and names any
   problem — a missing file, an unknown field, a verdict that is not in the taxonomy.

## Label shape

```jsonc
{
  "name": "b01_bourbon_straight_on",
  "commodity": "spirits",                 // spirits | wine | malt
  "images": [
    { "file": "b01_front.heic", "role": "front" },
    { "file": "b01_back.heic",  "role": "back"  }   // role: front | back | single
  ],
  "application": {                        // the COLA-style record to verify against
    "commodity": "spirits",
    "brand_name": "…",
    "class_type": "…",
    "alcohol_content": 45.0,              // null when the label carries none
    "net_contents": "750 mL",
    "producer_name": "…",
    "producer_address": "…",
    "country_of_origin": null,
    "is_import": false
  },
  "expect": {                             // omit a field to expect a clean Match
    "government_warning": "match"
  },
  "expect_findings": {},                  // field -> finding codes that must be raised
  "capture": {
    "conditions": "straight on, indoor daylight, no flash",
    "device": "phone",
    "format": "heic"
  },
  "ground_truth": "bootstrapped",         // bootstrapped | hand_verified
  "notes": "Why this bottle is in the set — which TC row or real-world condition it covers."
}
```

`application` is the same object `POST /verify` takes. `expect` values come from the
verdict taxonomy: `match`, `acceptable_variation`, `mismatch`, `missing`, `unreadable`,
`not_applicable`.

## Running it

```bash
python -m eval.run --tier b      # Tier B alone
python -m eval.run --tier all    # both, reported separately, with the A↔B gap
```

Both need `ANTHROPIC_API_KEY` — real photographs need a real extractor. Without one the
run prints `SKIPPED` and exits `0`; it is never a failure, and it never changes the exit
code of the Tier A gates.

## What this set can and cannot show

It can show whether the pipeline reads commercial typography, curved glass, foil, real
glare and phone-camera noise.

It **cannot** show whether warning-statement violations are caught under real optical
conditions. A commercially approved label does not carry a title-case header or a bold
body — by definition, or it would not have been approved. Those cases stay simulated in
Tier A, and that limitation belongs in the submission's limitations list rather than in a
footnote nobody reads.
